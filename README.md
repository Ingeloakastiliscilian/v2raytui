# v2rayn-tui

Терминальный интерфейс (TUI) к движку [v2rayN](https://github.com/2dust/v2rayN): те же подписки,
форматы ссылок, генерация конфигов xray / sing-box, маршрутизация, системный прокси и TUN —
плюс **параллельный замер серверов из подписок**, в том числе **в фоне** (по расписанию,
с автопереключением на лучший сервер) и в headless-режиме `daemon` для systemd.

## Как устроено

- `external/v2rayN` — git-submodule с исходниками v2rayN (закреплён на коммите). Используется только
  UI-независимая библиотека `ServiceLib`: БД (SQLite), парсеры ссылок, подписки, генерация конфигов,
  управление процессами ядра, системный прокси, обновление ядер/geo. **Код v2rayN не изменён.**
- `src/V2RayTui` — наш код (.NET 10, [Terminal.Gui v2](https://github.com/gui-cs/Terminal.Gui)):
  - `Engine/TestService.cs` — параллельный тестер;
  - `Engine/BackgroundScheduler.cs` — фоновый цикл «[обновить подписки] → тест → [автопереключение]»;
  - `Engine/ProxyController.cs` — основное ядро, системный прокси, маршрутизация, TUN, сторож процесса;
  - `Tui/` — интерфейс; `Cli/` — команды и daemon.

### Параллельный замер

v2rayN проверяет серверы одним процессом ядра за раз, а замер скорости — последовательно.
Здесь:

1. Серверы делятся на пачки (`BatchSize`, по умолчанию 100). Для каждой пачки генерируется
   штатный speedtest-конфиг v2rayN — один процесс xray/sing-box с отдельным локальным socks-входом
   на каждый сервер.
2. Одновременно работает несколько таких процессов (`ParallelCores`, 4). Генерация конфигов и старт
   ядер сериализованы до момента, когда ядро реально слушает порты, — поэтому порты не пересекаются.
3. Пинги (`PingConcurrency`, 64) и загрузки (`SpeedConcurrency`, 3) ограничены **глобально** — ручной
   и фоновый тест, идущие одновременно, делят один бюджет.
4. Если ядро отвергает конфиг пачки (один «битый» сервер), пачка делится пополам, пока битый сервер
   не будет найден, — остальные всё равно проверяются.
5. Режим `ping+speed`: сначала real-ping всех, затем замер скорости только топ-N самых быстрых живых.

Результаты пишутся туда же, куда их пишет v2rayN (`ProfileExItem`), поэтому видны и в GUI.
Для ориентира: 270 серверов real-ping — около 7 с, включая запуск ядер.

### Фоновый режим

- В TUI тесты не блокируют интерфейс: можно листать, подключаться, запускать другие тесты.
  Прогресс — в строке статуса.
- Планировщик (`F2 → Тесты и фоновый режим`): интервал, режим теста, какие подписки, обновлять ли
  подписки перед тестом, тестировать ли после обновления подписки, автопереключение:
  - **Failover** — переключиться на лучший живой сервер, только если активный умер;
  - **Fastest** — ещё и если другой быстрее на заданный порог (%).
- Сторож: если процесс ядра неожиданно завершился, он перезапускается.
- Работает и планировщик самого v2rayN (автообновление подписок по их интервалу, geo-файлы).
- `q → В фон`: TUI закрывается, вместо него запускается `daemon` (прокси продолжает работать).
  При следующем запуске `v2rayn-tui` предложит остановить daemon и открыть TUI.

### Группа Alive — всегда актуальный набор рабочих быстрых серверов

`F2 → Группа Alive`: включить, задать минимальную скорость (МБ/с), при желании — максимальную
задержку, период перепроверки, число одновременных замеров скорости в фоне (по умолчанию 1)
и автопереключение (по умолчанию выключено).

Каждый фоновый цикл (в TUI и в `daemon`):

1. обновляются подписки — только те, что обновлялись больше часа назад (см. ниже);
2. параллельно пингуются все серверы (кроме самой группы Alive);
3. у **всех** ответивших меряется скорость — по умолчанию **по одному серверу за раз**: каждый
   получает весь канал, результаты сравнимы между серверами и между циклами;
4. группа пересобирается: новые подходящие серверы добавляются, выпавшие (мёртвые, медленные,
   пропавшие из подписок) удаляются, остальные остаются **с прежними id**. Один и тот же сервер
   из разных подписок попадает в группу один раз;
5. если включено автопереключение — выбор сервера внутри Alive. **Если выключено (по умолчанию),
   активный сервер никогда не меняется сам**: даже выбывший из проверки, он остаётся в группе,
   пока вы не переключитесь.

Alive — группа без URL, поэтому обновление подписок её не затрагивает. Если в цикле не нашлось ни
одного подходящего сервера (например, пропал интернет), группа остаётся прежней.
Цикл при замере по одному длится примерно «живые серверы × таймаут замера» (10 с по умолчанию);
следующий начинается через заданный период после окончания предыдущего.
`v2rayn-tui cycle` — один такой цикл из командной строки (например, из cron).

### Частота обновления подписок

Каждая подписка запрашивается **не чаще раза в час** (`SubUpdateMinIntervalMinutes`, настраивается
в `F2 → Группа Alive`). Правило общее: фоновые, ручные (`u`/`U`), CLI-обновления и встроенное
автообновление v2rayN (интервалы меньше часа поднимаются до 60 мин). Считаются и неудачные попытки.
Вручную можно обновить принудительно — TUI спросит подтверждение, в CLI — `sub update --force`.

## Сборка и установка

Нужен .NET SDK 10.

```bash
git clone --recurse-submodules <этот репозиторий>
cd v2ray
dotnet build src/V2RayTui                       # отладочная сборка
dotnet run --project src/V2RayTui               # запуск

# самодостаточный single-file бинарник (≈95 МБ, .NET на целевой машине не нужен)
dotnet publish src/V2RayTui -c Release -r linux-x64 --self-contained -o publish
install -m755 publish/v2rayn-tui ~/.local/bin/
```

При первом запуске TUI предложит скачать xray, sing-box и geo-файлы (или `v2rayn-tui core update`).

## Каталог данных и совместимость с v2rayN

По умолчанию данные лежат в `~/.local/share/v2rayN` (или `$XDG_DATA_HOME/v2rayN`) — **там же, где их
хранит v2rayN desktop на Linux**: подписки, серверы, маршруты и результаты тестов общие.
`--portable` — хранить данные рядом с бинарником.

Одновременно с GUI на одном каталоге работать нельзя: TUI откажется запускаться, если видит запущенное
ядро из этого каталога (именованный mutex v2rayN для этого не годится — в .NET на Linux он привязан к
сессии входа). Внутри TUI/daemon/CLI единственность обеспечивает файловая блокировка.

Для **нового** конфига TUI ставит системный прокси в режим «не менять» (у v2rayN по умолчанию —
«очистить»), чтобы не трогать настройки рабочего стола без спроса. Меняется клавишей `F3`.

## Использование

### TUI — основные клавиши (`F1` — полная справка)

| Клавиша | Действие | Клавиша | Действие |
|---|---|---|---|
| `Enter` | подключиться к серверу | `r` / `t` | real-ping / tcping (отмеченных или всех видимых) |
| `Space`, `*` | отметить / все | `s` / `m` | пинг+скорость / пинг всех → скорость топ-N |
| `i` | детали, ссылка, **QR-код** | `Esc` / `x` | стоп моих тестов / всех, включая фоновые |
| `c` | скопировать ссылку(и) | `o` / `O` | сортировка по задержке / скорости |
| `p`, `v`, `Q` | импорт: вставка / буфер / QR-картинка | `u` / `U` | обновить подписку / все |
| `Del`, `D`, `X` | удалить / дубликаты / нерабочие | `a`, `e` | добавить / изменить подписку |
| `[ ] { }` | переместить сервер | `/` | фильтр |
| `F3` `F4` | системный прокси / правила маршрутизации | `F5` `F6` | перезапуск / остановка ядра |
| `F7` | TUN (спросит пароль sudo) | `F8` | обновить ядра и geo-файлы |
| `F9` | фоновый цикл сейчас | `b` | фоновые тесты вкл/выкл |
| `F2` | настройки | `q`, `F10` | выход / уйти в фон |

Горячие клавиши работают и в русской раскладке. Ссылки можно просто вставить в окно терминала.

### Маршрутизация и разделение трафика (`F4`)

- **Наборы правил**: `Space` — сделать активным, `Enter` — правила, `a` — новый, `c` — копия,
  `e` — свойства (название, URL правил, доменные стратегии), `Del` — удалить,
  `i` — добавить встроенные наборы v2rayN, `1`/`2` — общая доменная стратегия xray / sing-box.
- **Правила** (срабатывает первое подходящее сверху): `a` — добавить, `Enter` — изменить,
  `Space` — вкл/выкл, `[ ] { }` — порядок, `Del` — удалить, `s` — сохранить;
  обмен в формате v2rayN: `c` / `C` — скопировать правило / все в JSON, `p` — вставить JSON,
  `f` — из файла, `u` — загрузить по URL набора.
- **Правило**: куда направить (прокси / напрямую / блок / конкретный сервер), домены (`geosite:`,
  `domain:`, `full:`, `regexp:`…), IP (`geoip:`, CIDR), порты, сеть, протоколы, входы и
  **приложения** — кнопка «Добавить запущенное приложение…» показывает процессы.
  Правила для приложений перехватывают весь трафик приложения в режиме TUN (`F7`).
- После сохранения активного набора ядро перезапускается само.

### CLI

```bash
v2rayn-tui status                               # каталог данных, запущен ли daemon, ядра
v2rayn-tui sub add 'https://…' --name prov --interval 60
v2rayn-tui sub update                           # все подписки, не чаще раза в час (--proxy, --force)
v2rayn-tui test -m ping                         # параллельный real-ping всех серверов
v2rayn-tui test -s prov -m pingspeed -n 10 --sort   # пинг + скорость топ-10, сохранить порядок
v2rayn-tui test --json > results.json
v2rayn-tui use best                             # сделать активным самый быстрый
v2rayn-tui cycle                                # один фоновый цикл: подписки → тесты → Alive
v2rayn-tui import links.txt                     # или: … | v2rayn-tui import -
v2rayn-tui core update                          # xray + sing-box + geo
```

### Daemon / systemd

```bash
v2rayn-tui daemon [--log FILE] [--test-now] [--no-core]
cp contrib/v2rayn-tui.service ~/.config/systemd/user/
systemctl --user enable --now v2rayn-tui
systemctl --user reload v2rayn-tui              # перечитать tui.json и запустить цикл сейчас
v2rayn-tui stop
```

Настройки фонового режима хранятся в `guiConfigs/tui.json` рядом с `guiNConfig.json`.

## Что не перенесено из GUI

- Ручное создание/редактирование сервера по полям протокола — сервер добавляется ссылкой
  (`p`/`v`/`Q`, как «Импорт из буфера» в v2rayN), редактируется повторным импортом.
- Настройки DNS и полного шаблона конфига, часть общих настроек (TUN: стек/MTU, ядро по
  протоколам, фрагментация и т.п.), группы серверов, статистика трафика, Clash-панели,
  резервная копия / WebDAV.
- Самообновление v2rayN не нужно; ядра и geo-файлы обновляются через `F8` / `core update`.
